# Anti-AI-Slop（birusupi 用）

出典は [Leonxlnx/taste-skill](https://github.com/Leonxlnx/taste-skill) の Section 9（AI Tells）と Pre-Flight Check。
本家は React/Next/Tailwind/GSAP のランディングページ用なので、**このサイト（Jekyll + Liquid + 手書きSCSS + 日本語）に効く部分だけを抜き、日本語向けに補正した**もの。本家のスタック指示・デザインシステム選定・ダイヤル（VARIANCE/MOTION/DENSITY）・GSAP スケルトンは**採用していない**。

---

## 1. 約物（日本語サイト向けに補正）

本家は em-dash を全面禁止するが、それは英語コピー前提のルール。ここでは**言語で分ける**。

### 日本語の文中 — 許可、むしろ正しい

| 文字 | 用途 | 判定 |
|---|---|---|
| `―`（U+2015 HORIZONTAL BAR） | 二倍ダーシ `――`、引用の話者表示 `―――ユパ` | **OK**。日本語の正規の約物 |
| `〜`（U+301C） | 範囲・程度 | **OK** |
| `…`（U+2026） | 三点リーダー。日本語では `……` と2つ重ねるのが正式 | **OK** |

**日本語文中で禁止**:
- `—`（U+2014 EM DASH）を日本語のダーシとして使う。`——` は `――`（U+2015×2）に直す
- `–`（U+2013 EN DASH）を日本語のダーシとして使う

### 英語コピーの中 — 本家のルールを適用

- **`—`（em-dash）は使わない。** 見出し、ラベル、ボタン文言、本文、引用の出典表記、alt テキスト、すべて。
  - 代替: ピリオドで2文に割る / カンマ / 丸括弧 / コロン
  - 出典表記は ` - `（前後スペース付きのハイフン）か改行
- **`–`（en-dash）を区切りとして使わない。** ただし**日付・数値の範囲は en-dash が正しい**ので例外（`12/11–12/13`、`€40-80k` のような通貨幅はハイフンでも可）。本家は範囲もハイフンと言うが、組版として過剰なので採用しない。

### 中黒 `·`（U+00B7）

- メタ情報の区切りとして**1行に最大1つ**。`foo · bar · baz · qux` は禁止
- 区切りが多く要るなら改行・罫線・カラムに逃がす
- 日本語の並列の中黒 `・`（U+30FB）は別物。**OK**

## 2. コピーの Tells（このサイトで実際に出たもの）

### ポエムラベル — 禁止

肩書きめいた飾りラベル。実際に `Signal Terminal` / `Lost in Transit` が出て削除した。

禁止例: `Signal Terminal` / `Lost in Transit` / `Field notes` / `From the field` / `観測メモ` を飾りとして使う / `Now working on` 的な気取った見出し

代わりに: 機能をそのまま言う（`Blog`、`最新の記事`、`テストの記録`）か、ラベル自体を置かない。

### セクション番号つきラベル — 禁止

`00 / INDEX`、`001 · Capabilities`、`06 · how it works`、`Stage 1 / Stage 2`、`Step 1 / Step 2`、`Phase 01`。
**手順の中身がラベルになる。** 「Stage 1: インストール」ではなく「インストール」。

### 大文字小ラベル（eyebrow）の個数制限

見出しの上に置く `uppercase tracking` 系の小さいラベルは、
**ページ内のセクション数 ÷ 3（切り上げ）が上限**。

このサイトでは `.page-kicker` / `.section-kicker` / `.home-card-kicker` を**全廃済み**。
新しく eyebrow を足すときは、なぜそれが必要かを一文で言えること。言えないなら置かない。

### 見出し下のマイクロ説明文 — 禁止

セクション見出しのすぐ下に置く、内容を補足する短文。
実際に 404 ページの「古いリンクから到達した場合は、上の主要ページから辿り直すのが最短です。」が該当して削除した。

**見出し + 本文で足りる。** 説明の説明を置かない。

### 埋め草の動詞・形容 — 禁止

英語: `Elevate` / `Seamless` / `Unleash` / `Next-Gen` / `Revolutionize` / `Empower`
日本語: 「シームレスな」「次世代の」「体験を再定義」「〜を加速させる」「〜に寄り添う」

具体的な動詞に置き換える。置き換えられないなら、その一文は要らない。

### 三点リーダーで濁す締め — 禁止

「〜かもしれません。」「〜ではないでしょうか。」で終わる段落が連続したら、書き手が言い切りを避けている。
**このサイトの本文は肉声で書く。** 断定できるものは断定する。

### 箇条書きの機械的な対称性 — 注意

3項目が全部同じ長さ・同じ構文で並んでいたら、内容ではなく形に合わせて書いている。
項目数は内容が決める。2つで足りるなら2つ。

## 3. UI / レイアウトの Tells

このサイトで**現時点で該当なし**の項目。新しく作るときに踏まないこと。

- **3列均等カード禁止。** 「同じカードが横に3つ」はLLMの既定形。現状は2列グリッドのみ
- **スクロール誘導禁止。** `Scroll` / `↓ scroll` / `スクロールしてご覧ください` / マウスホイールのアニメーション
- **装飾ステータスドット禁止。** ナビ項目やリスト行の前に置く色付きの丸。実際の状態を表す場合のみ、1セクション1個まで
- **バージョンラベル禁止。** `v1.4.2` / `Build 0048` / `BETA` / `EARLY ACCESS`
- **画像の上にピル/タグを重ねない。** キャプションは画像の下に、一行の機能的な文で
- **写真クレジット風の飾り禁止。** `Field study no. 12 · 撮影者名` 形式。実在の撮影者を実際にクレジットする場合のみ
- **ロケール・時刻・天気ストリップ禁止。** `Tokyo 14:23 · 18°C` のようなヘッダ/フッタの雰囲気表示
- **長いリストの全行に border-top + border-bottom を両方つけない。** どちらか一方を、控えめに
- **div で作った偽スクリーンショット禁止。** 実画像を使うか、置かない
- **`01 / 4` 形式のページ番号ラベル禁止。** 数えられるものに番号は要らない

## 4. このサイト固有の前提

- **スタック**: Jekyll + Liquid + kramdown + 手書きSCSS（`_sass/` + `assets/css/main.scss`）。React/Tailwind/GSAP は使わない
- **記事の `tags:` front matter** は OGP `article:tag` と JSON-LD `keywords` 用のメタデータ。タグ一覧ページは廃止済みなので、**タグへのリンクを新設しない**
- **nav** は `_data/settings.yml` の `menu` がデータソース。`_includes/header.html` にリンクをハードコードしない
- **本文の声**: `pages/about.md` の文体が基準。「気ままにやっている個人サイトです」「インターネットの片隅でひっそりやってます」— この温度を守る。マーケコピーに寄せない
- **未使用の表示文字列を残さない。** レンダリングされない `_data/settings.yml` のキーは消す（放置するとポエムコピーの温床になる）

## 5. 公開前チェック

記事・ページ・レイアウトを足したり書き換えたら、これを通す。

- [ ] 日本語文中に `—` / `–` をダーシとして使っていないか（`―` はOK）
- [ ] 英語コピーに `—` が1つも無いか。`–` は日付・数値の範囲だけか
- [ ] 中黒 `·` が1行に2つ以上並んでいないか
- [ ] ポエムラベル（`Signal Terminal` 系）を足していないか
- [ ] セクション番号つきラベル（`01 / ...`、`Step 1`）を足していないか
- [ ] eyebrow を足したなら、必要な理由を一文で言えるか
- [ ] 見出しのすぐ下にマイクロ説明文を置いていないか
- [ ] 埋め草の動詞・形容（「シームレスな」「次世代の」）が無いか
- [ ] 「〜かもしれません」で濁す段落が連続していないか
- [ ] 箇条書きの項目数を、内容ではなく見た目の対称性で決めていないか
- [ ] 3列均等カード / スクロール誘導 / 装飾ドット / バージョンラベルを足していないか
- [ ] 画像の上にピルを重ねていないか。キャプションは画像の下か
- [ ] 新しく追加した表示文字列が、実際にレンダリングされるか

1つでも引っかかったら直してから出す。

## 6. 採用しなかった本家のルール（意図的）

作業中に本家を参照した場合、以下は**このサイトでは適用しない**。理由を添えて残す。

| 本家のルール | 不採用の理由 |
|---|---|
| em-dash 完全禁止（例外なし） | 日本語の `―` は正しい約物。英語コピーにのみ適用する |
| 日付範囲もハイフン | 組版として en-dash が正しい。`12/11–12/13` は維持 |
| React / Next / Tailwind / shadcn / GSAP 前提 | Jekyll + 手書きSCSS。適用先がない |
| ダイヤル既定 `8 / 6 / 4` | 本家の推論表でも editorial/blog は `5-6 / 3-4 / 2-3`。既定値が攻めすぎ |
| ダークモード必須 | 現状ライト固定。要望が出たら別途 |
| Inter 禁止 / Phosphor・HugeIcons 強制 | 現状 FontAwesome。差し替えは別案件 |
| 生成前に「Design Read」を一行宣言 | ブログ記事の執筆には過剰な儀式 |
| Picsum / 生成画像を使え | 実際に撮った写真と作品画像を使うサイト |
